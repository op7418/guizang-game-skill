# 踩坑清单（按症状查）

## 游戏打不开、一直"载入中"、点击没反应
- **先看浏览器控制台**，不要先猜网络。最常见的是脚本语法错误导致入口模块根本没执行。
- 如果代码是"一行很长"的风格，**行尾不能加 `//` 注释**，它会吞掉同一行后面的代码。用 `/* */`。
- `node --check 文件.js` 对带 `import` 的模块文件可能查不出错。用 `node --input-type=module --check < 文件.js`。
- 不要依赖外网加载库。把 three.js 和用到的扩展模块放进项目里。

## 角色一直往一边走、身体不在脚下光圈上
预设动作的根位移没去干净。见 `characters-animation.md`。

## 按键相关（这一类最容易越修越坏）
- **松手后角色还在走 / 贴墙卡住几秒**：某个方向键的松开事件丢了（按住 Cmd 或 Alt 时、切窗口时都会丢），那个键一直留在"按住"集合里。
  - 有效的修法：按下一个方向键时，把它的反方向键从集合里删掉；任何修饰键按下或松开、窗口失焦或重新聚焦时清空集合。
  - 清空规则里的修饰键只包括 Cmd、Alt、Ctrl，**不要把 Shift 算进去**：Shift 常被用作冲刺或飞行键，算进去会让按 Shift 时方向键全部失效。
  - **不要**用"没收到按键重复事件"来推断松键。系统只对最后按下的那个键发重复事件，先按住的键会被误杀，表现为"按着突然停""同时按两个键只走一个方向"。
  - **不要**每帧轮询窗口是否有焦点来清空按键，在内嵌浏览器里这个值不可靠。
- 抓不到原因时，加一个调试面板（例如按 F3）：显示当前按住的键、角色状态、速度、离边界距离、焦点、最近八次按键事件。让用户在出问题时截图。**一张截图就能分清是按键丢了还是逻辑问题**。
- 鼠标右键按住的状态要在鼠标移动事件里用 `buttons` 重新同步。

## 贴墙、进场后动不了
- 关闭可走区域时把人留在了孤岛上。见 `combat-feel.md` 的"场地"。
- 碰撞解不开时退回上一帧位置，永远不接受一个非法位置。

## 画面
- 特效一片白：泛光过曝，降颜色峰值。
- 草叶被拉成长条：弯曲量要除以实例的水平缩放。
- 镜头钻进山体或被建筑挡死：见 `combat-feel.md` 的"镜头"。
- 过场结束镜头跳一下：过场终点没有对齐游戏镜头。
- 给透明度做过渡的遮罩在后台标签页里不走时间，自动测试截到黑屏不代表坏了，查计算后的样式值。

## 测试
- 标签页隐藏时不渲染，要用手动推进帧的钩子。
- 逐帧推进后截图偶尔是旧画面，以状态数值为准。
- 测试脚本里用定时器的逻辑（例如延迟释放）要改成按游戏时间判断，否则手动推进时不触发。
- 自动测试页会出声，默认静音，测完切回标题页。
- 你和用户可能共用同一个浏览器标签页，你在里面导航会打断用户。

## 流程
- 用户提供了生成工具却不用，自己拼素材 → 整版被推翻。
- 没看参考就开工 → 整版被推翻。
- 说"完成了"但没实际看过 → 用户一打开就发现问题，信任下降。
- 生成工具低于确认阈值时会直接扣费不询问，批量提交前自己先算总数。
