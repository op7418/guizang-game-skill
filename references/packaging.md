# 压缩并打包成单个 HTML

目标：一个双击就能打开、不需要服务器和网络的 HTML。实战结果：资源从约 98MB 压到约 21MB，成品约 30MB。

配套脚本 `scripts/build_single_html.mjs` 是那次项目用的原样脚本，按你的目录和清单文件改一下就能用。依赖：`@gltf-transform/core`、`@gltf-transform/extensions`、`@gltf-transform/functions`、`meshoptimizer`、`sharp`、`esbuild`，以及系统里的 `ffmpeg`。

## 体积都在哪
生成的模型每个带一张 4096 的贴图（3MB 以上）加两三兆几何数据；角色还各有一份"只为取动作"的重复文件。所以：

1. **贴图**：缩到 1024（主角、Boss、大建筑 1536，掉落物 512），转 WebP。这一步省得最多。
2. **只用来取动作的文件**：把所有节点上的网格和蒙皮引用清掉再裁剪，只留骨骼节点和动画。裁剪时要保留叶子节点，否则骨骼会被当成空节点删掉。
3. **几何**：meshopt 压缩。运行时给模型加载器挂上对应的解码器（开发环境挂上也无害）。
4. **地面贴图**：缩到 1024。
5. **配乐**：重编码到 88kbps 左右。
6. 压缩结果按"源文件修改时间"做缓存，重复打包只要几秒。

## 怎么内嵌
- 用 esbuild 把入口模块打成一个压缩过的模块脚本，把 `three` 和扩展模块的引用解析到项目里的本地副本。
- 所有资源转成 data URL，放进一个全局表 `window.__A = { "assets/...": "data:..." }`。
- 两处接管：
  - 包一层 `fetch`：路径在表里就改取 data URL；以 `assets/` 开头但不在表里的返回 404（可选资源不存在时不报错）。
  - 给 three 的默认加载管理器设网址改写函数，贴图和模型加载器就都走这张表。
- HTML 里的 `<img src>` 和样式里的 `url(...)` 在打包时直接替换成 data URL。
- 内嵌脚本里的 `</script` 要转义。

## 验证
- 打开成品，确认**网络请求数为 0**（过滤掉 data URL 后列出资源条目）。
- 至少进一场战斗，确认角色、动作、贴图、界面图标、声音都在。几何压缩带量化，理论上可能影响蒙皮，逐个角色看一眼。
- 让用户在自己机器上双击打开验证一次；自动化浏览器工具不一定能打开本地文件路径。

## 在线托管：先出画面，再加载

单文件适合发给人；挂到网上（GitHub Pages 之类）时改用多文件站点，否则访客要等整个文件下完才看到东西。`build_single_html.mjs` 的同一批压缩产物另写一份到 `dist/site/`，代码单独一个带哈希的 js。

启动顺序按"需要什么才能画出第一帧"来排，而不是全部 `await` 完再开渲染循环：

1. HTML 里直接放标题图和进度条，脚本没到也有东西看。
2. 天空、地面、草、天气这些纯代码的东西先建好，等地表贴图到了就淡入并开始渲染循环（单独一个不依赖角色的 `pre()` 帧函数，镜头缓慢游移）。
3. 场景模型和角色同时下载。场景模型到齐就摆放，用一秒从地面长出来，由近到远错开，掩盖突然出现。
4. 角色到齐后切换到正式的帧函数，再显示"点击开始"。
5. 音乐等到点击开始之后再取。

进度条按文件数走即可（`loadGLB` 里计数），每到一个文件显示一行文案，用队列保证每行至少停留 0.17 秒，否则本地加载时一闪而过。文案可以贴合题材，旁边用小字写真实在做的事（"立山门 · 山门模型"），既有趣又不骗人。

实测参考：22MB 站点，限速约 20Mbps 时，脚本到达后约 1 秒出第一帧，全部就绪约 10 秒；在此期间画面一直在动。

## 带骨骼的角色不要做网格量化

`meshopt()` 默认会量化顶点：把网格缩放到整数范围，再把反向缩放放到骨架节点上。静态摆件没问题，带骨骼的角色会出两个错：按包围盒算身高的代码量到的是另一个空间的尺寸；平台预设动画每个节点都带"缩放 = 1"的轨道，一播放就把那个补偿缩放抹掉，角色当场缩小。症状是"开发版正常，打包版一跑动人就变小"或"Boss 只有一半高"。

做法：角色只做 `reorder` 加 `EXT_meshopt_compression`（不调用 `quantize`），体积比量化大三四成，但行为与未打包版一致。加载动画时顺手丢掉 `.scale` 轨道。

打包后必须逐个角色对比开发版和打包版的同一组数字（头部高度、根节点缩放、跑动时手脚摆幅），不能只看"能进游戏、没报错"。

## 手机与受限容器（小程序、小工具类平台）

触屏适配放在游戏本体里，所有构建共用：
- 左半屏按下的位置出现浮动摇杆，直接给移动向量加模拟量；技能图标本身变成右下角的按钮，按住类（格挡、冲刺）在 `pointerup / pointercancel / pointerleave` 都要松开。
- 触屏模式下忽略鼠标事件，否则每次点摇杆都会触发一次"左键攻击"。
- 手机没有鼠标指向：瞄准点取最近的敌人，其次摇杆方向，再次角色朝向。
- 竖屏横向视野太窄，把镜头视角从 36° 放到 50° 左右并稍微拉远；血条挪到顶部，底部留给拇指。
- 安全区不要写 `var(--x, env(...))`：旧内核不认识 `env()`，整条声明在计算时失效且不会回退到上一条。用脚本把值解析成普通长度写进自定义属性。
- 绘制缓冲区按像素预算封顶（`min(dpr, 1.5, sqrt(预算 / (宽×高)))`），掉帧时依次降分辨率、关阴影、关泛光、减草；页面隐藏时停循环，处理 `webglcontextlost`，不支持 WebGL 2 时给出说明而不是白屏。

平台容器常见的硬限制和对应做法（以小红书小工具为例，其它平台先读它自己的规范）：

| 限制 | 做法 |
|---|---|
| 不能 `fetch` / XHR | 打包时把 `fetch` 整体改写成本地查表函数（esbuild `define`），数据放进按需插入的经典脚本 |
| 只允许网页常规文件类型（没有 .glb / .mp3） | 模型拆成 glTF JSON + base64 缓冲区放进 .js，运行时在内存里拼成 GLB 交给解析器；贴图抽成独立 .webp；音频用 base64 交给 `decodeAudioData` |
| 不能用 WASM | 不用 meshopt / Draco 解码器；用构建期减面 + 把法线、UV、权重存成归一化整数（位置保持浮点） |
| 脚本必须外置、不能是模块 | esbuild `format: 'iife'`，`target: ['es2017','chrome61']`，HTML 里只留一个 `<script src>` |
| 包体上限（10MiB） | 角色减到一万面以内、贴图 512、长动画隔帧抽样、音乐降到单声道低码率 |
| three.js 的 GLTFLoader 会用 `createImageBitmap` + fetch 读贴图 | 打包时把 `createImageBitmap` 定义成 `undefined`，让它退回 `<img>` 加载 |

打包脚本末尾加一道静态扫描（禁用 API 的字样、内联脚本、外链、不允许的文件类型），不通过就不出包。浏览器里能跑不代表容器里能跑，交付时要写明哪些只在浏览器验证过。
